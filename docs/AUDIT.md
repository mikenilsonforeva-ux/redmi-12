# Аудит: диагностика сигнала FM для MT6631 (Redmi 12)

Статус на момент написания: **код проверен только компиляцией против заглушек Android API и юнит-тестом на JVM. На телефоне ничего не запускалось.** Все колонки «подтверждено на устройстве» ниже честно содержат «нет».

## 1. Что реально есть в исходниках

JNI-таблица в `jni/fmr/libfm_jni.cpp` (`methodsRx`) регистрирует **16 методов**: `openDev`, `closeDev`, `powerUp`, `powerDown`, `tune`, `seek`, `autoScan`, `stopScan`, `setRds`, `readRds`, `getPs`, `getLrText`, `activeAf`, `setMute`, `isRdsSupport`, `switchAntenna`.

В `FmNative.java` дополнительно объявлено 10 методов (`readRssi`, `stereoMono`, `setStereoMono`, `readCapArray`, `readRdsBler`, `emcmd`, `emsetth`, `getHardwareVersion`, `setDesenseChannel`, `setDesenseList`) с комментарием «needed for registerNativeMethods». Их нет в исходной JNI-таблице, поэтому, по всей видимости, их регистрирует **фабричная** `libfmjni.so` из HyperOS (она работает на телефоне, и `RegisterNatives` завершается успешно).

Это вывод, а не факт: фабричной библиотеки в архиве нет. Проверка на ПК (нужен файл `lib64/libfmjni.so` из распакованной прошивки):

```bash
strings -a libfmjni.so | grep -xE 'readRssi|stereoMono|setStereoMono|readCapArray|readRdsBler|emcmd|emsetth|getHardwareVersion'
```

Имя метода и его JNI-сигнатура лежат в таблице `RegisterNatives` рядом, как строки. Если имя есть, метод, скорее всего, зарегистрирован; если нет, экран покажет «Недоступно», и приложение не пострадает.

## 2. Таблица параметров

| Параметр | Java API | ioctl драйвера | Тип | Единицы | В экране «Сигнал» | Подтверждено на устройстве | Безопасность |
|---|---|---|---|---|---|---|---|
| RSSI | `FmNative.readRssi()` | `FM_IOCTL_GETRSSI` (`int32_t`) | `int` | **сырые**, не dBm | да | нет | только чтение |
| Стерео/моно | `FmNative.stereoMono()` | `FM_IOCTL_GETMONOSTERO` (`uint16_t`) | `boolean` | флаг; какое значение значит «стерео», не подтверждено | да, как сырой флаг 1/0 | нет | только чтение (`setStereoMono` не вызывается) |
| RDS BLER | `FmNative.readRdsBler()` | `FM_IOCTL_GETBLERRATIO` (`uint16_t`) | `short` | сырые, шкала не подтверждена | да | нет | только чтение |
| Массив ёмкостей антенны | `FmNative.readCapArray()` | `FM_IOCTL_GETCAPARRAY` (`int32_t`) | `short` | сырые, шкала не подтверждена | да | нет | только чтение |
| PAMD | нет Java-метода | `FM_IOCTL_GETCURPAMD` (`uint16_t`) | — | не подтверждены (в `common.cpp` есть таблица 5/10/15/20/25 dB ↔ 8/12/15/18/20, но для MT6631 она не проверена) | **нет**, нужен новый native-мост | нет | чтение, но мост нужно собирать и проверять |
| Good RDS blocks | нет Java-метода | `FM_IOCTL_GETGOODBCNT` (`uint16_t`) | — | счётчик | **нет**, нужен мост | нет | то же |
| Bad RDS blocks | нет Java-метода | `FM_IOCTL_GETBADBNT` (`uint16_t`) | — | счётчик | **нет**, нужен мост | нет | то же |
| CQI | нет Java-метода | `FM_IOCTL_CQI_GET`, `struct fm_cqi_req { uint16_t ch_num; int buf_size; char *cqi_buf; }` | `struct fm_cqi { int ch; int rssi; int reserve; }` | сырые | **нет** | нет | см. риск ниже |
| Full CQI log | нет Java-метода | `FM_IOCTL_FULL_CQI_LOG`, `{lower, upper, space, cycle}` | — | — | **нет** | нет | **не использовать**: запускает серию измерений по диапазону и может мешать приёму |
| RSSI при сканировании | нет Java-метода | `FM_IOCTL_SCAN_GETRSSI`, `struct fm_rssi_req` | — | сырые | **нет** (задача 7.4, отдельно) | нет | не запускать параллельно со штатным `autoScan()` |
| `emcmd()` | объявлен | — | `short[]` | — | **нет** | нет | формат и коды команд неизвестны, не вызывается по ТЗ |

### Риски, найденные при аудите

- **`fm_cqi_req` содержит указатель** (`char *cqi_buf`). Для 64-битного приложения и ядра раскладка структуры должна совпадать с драйвером MT6631 бит в бит. Это нужно сверить с исходниками драйвера до первого вызова, иначе возможна порча памяти ядра.
- В `fm_cqi` только поля `ch`, `rssi`, `reserve`. Полей PAMD/MR/ATDC, которые есть в других ветках MediaTek, здесь нет, поэтому «расширенные CQI-поля» из ТЗ в этой структуре не появятся.
- Кодировка `space` в `fm_full_cqi_log_t` (`0x1: 50KHz`) отличается от `fm_tune_t` (`5: 50KHz`). Подтверждение того, что значение понимает драйвер, нужно получить до использования.

## 3. Что реализовано (этап C, только подтверждаемое)

Экран «Диагностика сигнала» (пункт меню «⋮»): частота, состояние, график RSSI за ~2 минуты, четыре строки параметров из таблицы выше, время последнего успешного измерения.

- Опрос раз в секунду в отдельном потоке, только пока экран виден.
- Во время seek/scan, при выключенном радио и закрытом устройстве native-вызовы не делаются.
- Отсутствующий метод (`LinkageError`, в частности `UnsatisfiedLinkError`) отмечается как «Недоступно» и больше не вызывается.
- Ошибка чтения показывается как ошибка с временем последнего успеха; старое значение не выдаётся за новое.
- При смене станции график начинается заново.
- Никаких записывающих вызовов (`setStereoMono`, `emsetth`, `setDesense*`, `emcmd`) нет.

| Проверка | Результат |

| RSSI меняется при смене станции и положении антенны/наушников | не проверено |
| Стерео/моно: какое значение (1/0) соответствует стерео | не проверено |
| RDS BLER меняется на станции с RDS и без неё | не проверено |
| Массив ёмкостей антенны: значения осмысленны | не проверено |
| Какие из четырёх строк показывают «Недоступно» | не проверено |
| Seek, auto scan, stop scan, запись работают при открытом экране «Сигнал» | не проверено |
| Звук не прерывается при открытии/закрытии экрана | не проверено |
| После перезагрузки радио работает автоматически | не проверено |
